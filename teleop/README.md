# 폰 조그 텔레오퍼레이션 — MuJoCo 시뮬레이션

안드로이드 폰의 **조그 버튼**으로 MuJoCo 모델(`../mujoco/mjcf/scene_servo.xml`)의 양팔 끝단을 움직입니다.
폰의 모션 센서(자이로·가속도·지자기)는 **쓰지 않습니다.** 지금은 **시뮬레이션 전용**이고, MQTT 송신은 붙어 있지 않습니다.
배경 검토는 `docs/폰_텔레오퍼레이션_검토.md` 에 있습니다.

```
[폰 앱: 가로 화면, 왼쪽 LA / 오른쪽 RA 조그 패드] ──TCP──▶ [teleop_sim.py]
   USB   : 앱 → 127.0.0.1:5001 ─adb reverse─▶ PC:5001
   Wi-Fi : 앱 → PC_IP:5001       (PC가 UDP 5000으로 비컨 송신 → 앱 'PC 찾기')
                                   ├ 버튼 상태 × 속도 → 끝단 목표 적분 (양팔 독립)
                                   ├ DLS IK (MuJoCo 자코비안)
                                   └ 위치 서보 setpoint (중력보상 모델) + 뷰어
```

## 실행

```powershell
cd claude_ws\teleop
python android\build_apk.py --install     # 앱 빌드 + 연결된 모든 폰에 설치 (Gradle 불필요)
python teleop_sim.py                       # USB + Wi-Fi 둘 다 대기, 뷰어 열림
```

폰에서 **Humanoid Teleop** 앱을 엽니다(가로 고정).

1. 연결 방식 선택 후 **연결**
   - **USB**: 케이블 연결 + USB 디버깅 허용만 하면 됩니다. `teleop_sim.py`가 2초마다 연결된 폰을 찾아 `adb reverse tcp:5001 tcp:5001`을 걸어 줍니다(핫플러그 대응).
   - **Wi-Fi**: PC와 같은 네트워크에서 **PC 찾기**(UDP 비컨) 또는 IP 직접 입력.
     Windows 방화벽이 python.exe 허용을 물으면 "개인 네트워크"를 허용하세요.
2. 화면 **왼쪽 절반이 왼팔(LA), 오른쪽 절반이 오른팔(RA)** 입니다(로봇 뒤에서 같은 방향을 보고 선 기준). 팔 선택은 없습니다.
3. 버튼을 **누르고 있는 동안만** 그 축으로 움직이고, 떼면 그 자리에 멈춥니다. 여러 버튼(양팔 포함)을 동시에 누를 수 있습니다.
4. **양팔 초기자세**: 두 팔을 `rmd_ic` 자세로 되돌립니다.

| 버튼 | 베이스 좌표계 (기본) | 툴 좌표계 (체크 시) |
|---|---|---|
| X± / Y± / Z± | 앞뒤 / 왼오른 / 위아래 이동 (base: x 앞, y 왼쪽, z 위) | 툴 사이트의 x / y / z 축 방향 이동 |
| Rx± / Ry± / Rz± | 베이스 축에 평행한 축으로, 툴 점을 중심으로 회전 | 툴 자신의 축으로 회전 |

| 속도 | 이동 | 회전 | 바꾸려면 |
|---|---|---|---|
| 느림 / 보통 / 빠름 | 20 / 50 / 100 mm/s | 10 / 25 / 45 °/s | `--lin-speed 0.02,0.05,0.10 --ang-speed 10,25,45` |

안전 장치
- 폰은 버튼 상태를 50 Hz로 계속 보냅니다. PC는 **0.2초 동안 수신이 없으면 정지**합니다(`--watchdog`). 연결이 끊기거나 앱이 백그라운드로 가도 팔이 계속 움직이지 않습니다.
- IK 오차가 5 mm / 3°를 넘으면 "한계 도달"로 보고, 목표를 팔이 실제로 도달한 자세로 되돌립니다. 버튼을 계속 눌러도 목표가 팔 밖으로 쌓이지 않고, 반대 버튼에 바로 반응합니다.
- 관절 속도 상한은 3 rad/s입니다. q6 범위는 서보 모델의 ctrlrange(손목 평행링크 특이자세 10° 안쪽)로 제한됩니다.
- 폰 여러 대가 연결되면 마지막에 버튼 상태를 보내기 시작한 폰이 양팔을 제어하고, 나머지 폰에는 "[다른 폰이 제어 중]"이 표시됩니다.

## 검증한 것 (2026-10-06)

| 항목 | 결과 |
|---|---|
| 실제 폰(Galaxy A15), Wi-Fi | LA Z+ 1.5 s → +74 mm, RA X+ 1.5 s → +75 mm (보통 속도 기대값 75 mm), 떼면 정지, 다른 팔은 그대로 |
| 실제 폰, USB(adb reverse) | 접속·조작 확인 (센서 방식이던 이전 버전에서 확인, 전송 경로는 같음) |
| 베이스 좌표계 (`fake_phone.py`) | Z+ 2 s → +100 mm, Y− 1 s → −50 mm, Rz+ 2 s → 50.0° |
| 툴 좌표계 (LA) | 툴 축 방향(월드에서 기울어진 축)으로 정확히 이동·회전 |
| 양팔 동시 입력 | 두 팔 모두 같은 변위, 한 팔만 보낸 경우 다른 팔 고정 |
| 신호 끊김 | 송신 중단 0.2 s 뒤 "신호 끊김 - 정지", 재개 시 정상 동작 |
| 시뮬 서보 추종 | 명령 대비 툴 위치 오차 0.0 mm (중력보상 + 위치 서보) |

## 프로토콜

한 줄 = 한 메시지(UTF-8).

```
폰 → PC  H 4 <기종>
         K <seq> <속도 0|1|2> <좌표계 B|T> <RA: vx vy vz wx wy wz> <LA: vx vy vz wx wy wz>   (각 −1/0/+1, 50 Hz)
         E HOME ALL
PC → 폰  ST <상태 문자열>          (10 Hz, 앱 상단 파란 글씨)
```

## 파일

| 파일 | 역할 |
|---|---|
| `teleop_sim.py` | 메인. 조그 적분, DLS IK, 감시(watchdog), MuJoCo 시뮬·뷰어(양팔 목표 프레임 화살표; 움직일 때 진하게) |
| `phone_server.py` | TCP 서버(USB/Wi-Fi 공용), `adb reverse` 유지(`UsbReverser`), UDP 비컨 |
| `adb_tools.py` | adb 탐색, 기기 목록, reverse 설정/해제 |
| `fake_phone.py` | 폰 없이 PC 쪽을 시험하는 스크립트 클라이언트 (`--arm RA|LA|both`, `--tool`, `--drop`) |
| `android/` | 앱 소스(Java, 리소스·라이브러리 없음)와 `build_apk.py` (aapt2 → javac → d8 → zipalign → apksigner) |

IK는 C++ `RobotArm7`이 아니라 **같은 rmd에서 생성·검증된 MuJoCo 모델의 자코비안**으로 풉니다(시뮬레이션과 같은 기구학, 별도 빌드 불필요).
실기로 갈 때 C++ IK + MQTT q 송신으로 바꾸려면 `ArmJog.update()`의 `self.ik.solve(...)` 호출과 `d.ctrl` 대입 자리만 교체하면 됩니다.
