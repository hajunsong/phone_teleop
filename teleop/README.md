# 폰 조그 텔레오퍼레이션 — 폰에서 IK + MQTT 발행

안드로이드 폰 앱이 **IK를 직접 풀고**, 로봇의 지령 토픽 `/humanoid/upper/cmd/joint` 로 **MQTT를 직접 발행**합니다.
지금은 PC의 MuJoCo 시뮬레이션(`teleop_sim.py`)이 로봇 역할을 합니다. 같은 앱을 실기 브로커(`192.168.0.142:1883`)에 붙이면 실기 경로가 됩니다.
배경 검토는 `docs/폰_텔레오퍼레이션_검토.md`, 토픽 사양은 `humanoid_control/Mqtt/TOPICS.md` 에 있습니다.

```
[폰 앱]  조그 → 목표 자세 → DLS IK(관절 한계 고려) → q(14)
   │      3D 뷰: 실제 CAD 메쉬를 폰 FK로 그림
   │ MQTT  pub /humanoid/upper/cmd/joint   [0,0, LA q1..q7, RA q1..q7, servo(, gain)]  50 Hz
   │       sub /humanoid/upper/joint_state {"pos_rad":[16]}  → 연결 시 현재 자세에서 시작
   ▼
[브로커]  USB  : PC 내장 브로커 :1883 ← adb reverse tcp:1883 ← 폰 127.0.0.1:1883
          Wi-Fi: PC 내장 브로커(UDP 5000 비컨으로 탐색) 또는 실기 브로커 192.168.0.142
   ▼
[teleop_sim.py]  지령 검증(브리지와 같은 규칙) → MuJoCo 위치 서보 → joint_state 100 Hz 발행
```

## 실행

```powershell
cd claude_ws\teleop
python export_phone_model.py              # rmd → MuJoCo 모델이 바뀌었을 때만: 폰용 모델/메쉬 재생성
python android\build_apk.py --install     # 앱 빌드 + 연결된 모든 폰에 설치 (Gradle 불필요)
python teleop_sim.py                      # 내장 브로커 :1883 + 시뮬 + 뷰어, USB·Wi-Fi 둘 다 대기
```

브로커를 시뮬과 **따로** 띄우면, 시뮬 창을 닫거나 다시 띄워도 폰 연결이 유지됩니다(권장).

```powershell
python broker.py                                                       # :1883, adb reverse, UDP 비컨, 토픽별 수신율 출력
python teleop_sim.py --broker 127.0.0.1 --publish-state --no-usb --no-wifi
```

`--publish-state`는 이 브로커에서 시뮬이 로봇 브리지 역할을 하기 때문에 붙입니다. 실기 브리지가 있는 브로커에서는 쓰지 마세요.

앱(가로 화면)에서

1. **USB** 또는 **Wi-Fi**를 고르고 **연결**합니다. Wi-Fi일 때는 **PC 찾기**가 IP와 포트를 채웁니다.
2. 연결되면 앱이 `joint_state`를 받아 **로봇(시뮬)의 현재 자세로 동기화한 뒤에** 발행을 시작합니다. 상태 칩이 "연결됨"으로 바뀌고 팔 배지가 "활성"이 됩니다.
3. 패드를 조작합니다. 왼쪽 패널이 LA, 오른쪽 패널이 RA이고, **팔을 고르는 단계 없이 양쪽 버튼을 동시에 누를 수 있습니다**
   (여러 손가락, 같은 팔의 여러 축도 가능). 3D 뷰는 로봇 뒤에서 본 시점이라 화면 왼쪽에 LA가 옵니다.

| 조작 | 동작 |
|---|---|
| 위치 패드 | Z+ 위 / Z− 아래, Y+ 좌 / Y− 우, X+ 앞 / X− 뒤. 가운데 ⌂는 위치만 초기 위치로 |
| 자세 패드 | Rx± / Ry± / Rz±. 가운데 ⌂는 자세만 초기 자세로 |
| 연속 이동 (버튼 유지) | 켜면 누르는 동안 이동하고, 끄면 탭 한 번에 한 스텝(패드 오른쪽 위 `20 mm ▾`, `2° ▾`) 이동 |
| 이동 속도 / 속도 모드 | 이동 5~150 mm/s, 회전 5~60 °/s, 관절 이동 10~60 °/s. 느림/보통/빠름은 15/50/85 % |
| 툴 좌표계 기준 | 끄면 base 좌표계(x 앞, y 왼쪽, z 위), 켜면 툴 축 기준 |
| 두 팔 동시 제어 (대칭) | 한쪽 패널 입력을 양팔에 좌우 대칭(y 반전)으로 적용 |
| 프리셋 | 초기자세, 현재 자세 저장, 저장 자세로 이동 — 모두 **양팔**에 적용, 관절 보간 |
| 양팔 초기자세 | 두 팔을 `rmd_ic` 자세로 관절 보간 이동 |
| 3D 뷰 | 한 손가락 드래그로 회전, 두 손가락으로 확대·축소. 좌표계 표시 시 툴과 base 좌표축 |
| 설정 | 토픽, 발행 주기, 게인 스케일, 서보 플래그, 상태 없이 발행 허용, 위치 우선 |

## 안전 설계 (실기 연결 전에 읽을 것)

- **서보 플래그 기본값은 0(서보 off)** 입니다. 실기를 움직이려면 설정에서 직접 켜야 합니다. 시뮬은 플래그와 상관없이 따라 움직입니다.
- **현재 자세 동기화**: 연결 후 `joint_state`를 받기 전에는 아무것도 발행하지 않습니다. 1.5초 안에 못 받으면 "발행 보류"로 멈춥니다(설정에서만 해제 가능).
  첫 지령이 항상 로봇의 실제 자세라서, 연결하는 순간 팔이 튀지 않습니다. 앱이 백그라운드에서 돌아올 때도 다시 동기화합니다.
- **연속 지령**: 모든 움직임이 속도 제한을 받는 목표를 따라가고, 프리셋과 초기자세 이동은 관절 보간입니다. 메시지당 관절 변화는 보통 속도에서 최대 약 1.2°입니다(시뮬 측정).
- **관절 한계**: 실기 측정 가동 범위(`joint_limits_robot.json`, 출처 `upper_control/workorder.md`)와 모델의 손목 평행링크 특이자세 여유(10°)의 교집합을 씁니다.
  IK는 한계에 닿은 관절을 잠그고 나머지 관절로 다시 풉니다.
- **한계 도달**: 따라갈 수 없으면 그 틱을 취소하고 멈춥니다(배지 "한계"). 버튼을 계속 눌러도 목표가 팔 밖으로 쌓이지 않고, 지시하지 않은 방향으로 새지 않습니다(축 밖 이동 1 mm 미만).
- **위치 우선 (기본 켬)**: 이동 버튼이 자세를 고정한 채로는 막힐 때, 손끝 자세를 **한 번 누를 때 최대 30°까지** 양보하고 위치를 지킵니다(배지 "자세 양보").
  초기자세에서는 팔꿈치(q4)가 한계에 1.9°밖에 안 남아 있어서, 이 기능이 없으면 Z+로 10 mm밖에 못 갑니다.
- **폰은 한 대만 연결합니다.** 두 폰이 동시에 연결되면 둘 다 같은 토픽에 50 Hz로 발행해 지령이 섞입니다(MQTT에는 제어권 중재가 없음).
  다른 폰을 쓰려면 먼저 연결된 폰에서 "연결 끊기"를 누릅니다.
- **동시 누르기 안전망**: 화면에서 마지막 손가락이 떨어지거나 시스템이 터치를 취소하면, 버튼별 해제와 상관없이 모든 조그를 해제합니다.
- q는 rmd 규약 그대로(라디안) 보냅니다. 14축 관절축과 영점이 제어기(`TcUpperBodyControl`)와 같습니다(`upper_control/kinematics_check.md`).

초기자세에서 버튼 하나를 계속 눌렀을 때 갈 수 있는 거리(PC 검사, 보통 속도):

| | X− | X+ | Y− | Y+ | Z− | Z+ | Rx | Ry− / Ry+ | Rz |
|---|---|---|---|---|---|---|---|---|---|
| RA·LA | 75 mm | 251 mm | 310 mm 이상 | 310 mm 이상 | 239 mm | 52 mm | ±117~130° | 101° / 9° | 91~130° |

## 검증

| 항목 | 결과 |
|---|---|
| 폰 FK (Java) vs MuJoCo, 무작위 200자세 | 직렬 링크·툴 위치 8e-16 m, 회전 1e-15. 손목 평행링크(렌더링용 선형근사) 0.17 mm |
| 폰 IK, 무작위 도달가능 목표 200개 | 200/200 수렴(0.1 mm, 0.06°), 1회 0.04 ms (PC JVM) |
| 조그 로직 (`ControllerCheck`) | 축 밖 이동 0.9 mm 이하, 연속 77.5 mm/s 정확, 스텝 + 대칭 ±20.0 mm, 툴 Rz 10.00°, 한계에서 쌓임 없음, 관절 이동 틱당 0.35° 상한 |
| 실제 폰(Galaxy A15) → Wi-Fi → 시뮬 | `joint_state` 동기화 후 50 Hz 발행. LA Z+ 연속 +52 mm, LA X+ 20 mm 스텝 2회 +20/+20 mm, RA X+ 2초 +157 mm(기대값 155 mm), 양팔 초기자세 복귀 |
| 실제 폰 → USB(adb reverse 1883) → 시뮬 | 접속(127.0.0.1)과 동기화, 조작 확인 |
| 지령 검증 | 잘못된 페이로드(`[1,2,3]`) 거부, 카운트 |
| 동시 누르기 (실제 폰, 3손가락) | LA Y+ · LA X+ · RA X+ 동시 1.5초 → LA +121/+125 mm, RA +117 mm, 떼면 정지 |

검사 재실행: `python tools\check_phone_kinematics.py` (FK·IK·조그 로직, Android Studio JDK 사용).
폰 없이 MQTT 경로 확인: `python fake_phone.py` (시뮬 실행 중).
동시 누르기 확인(실제 폰, 앱이 다중 포인터 터치 이벤트를 만들어 자기 화면에 보냄; 키는 `팔:축0~5:방향`):
`adb shell am start --activity-single-top -n com.humanoid.teleop/.MainActivity --es mt "LA:1:1,LA:0:1,RA:0:1" --ei mt_ms 1500`
(Git Bash에서는 앞에 `MSYS_NO_PATHCONV=1`)

| `broker.py` | 독립 실행 브로커(adb reverse, 비컨 포함). 시뮬과 분리해 폰 연결을 유지 |

| `fake_phone.py` | 폰 대역 MQTT 클라이언트(동기화, 50 Hz 발행, 잘못된 지령 1회) |

| `android/src/.../Controller.java` | 조그·스텝·대칭·툴 좌표계·프리셋·동기화, 한계/자세 양보 처리. Android 의존성 없음 |

| `android/src/.../RobotView.java` | OpenGL ES 3D 뷰 |

## 실기에 붙일 때

1. 폰을 로봇 네트워크(Wi-Fi)에 연결하고, IP `192.168.0.142` / 포트 `1883` 으로 연결합니다(이때 PC 시뮬은 필요 없습니다).
2. 연결 후 상태 칩이 "연결됨"이고 3D 뷰가 실기 자세와 같은지 확인합니다. 서보 플래그가 0이면 발행은 되지만 실기는 움직이지 않습니다.
3. 설정에서 서보 플래그를 켜고, 게인은 0.1부터 시작합니다. 첫 구동은 단일 축·소진폭·입회로 합니다(`TOPICS.md` 경고 참조).
4. 다른 PC(3D 마우스 PC1 등)가 같은 토픽에 발행 중이면 지령이 섞입니다. 한 번에 하나의 발행자만 둡니다.

PC 시뮬을 실기 브로커에 붙여 폰 지령을 MuJoCo로 같이 보려면 `python teleop_sim.py --broker 192.168.0.142` 를 씁니다.
외부 브로커에서는 시뮬이 `joint_state`를 **발행하지 않습니다**(실기 브리지와 겹치지 않게). `--publish-state`로만 켤 수 있고, 실기 운용 중에는 켜지 마세요.
