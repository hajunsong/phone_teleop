# 목표
- 안드로이드 폰 2대를 USB로 PC에 연결하고, 각 폰의 위치·자세를 받아 양팔(RA/LA) 끝단이 추종하도록 하는 윈도우 프로그램의 실현 가능성 검토

# 내용
- 현재 입력 장치는 3D mouse이며, PC1이 IK 결과 q1~q7 x 2를 MQTT로 송신 (`제어_방법_검토.md` 참고)
- 폰 텔레오퍼레이션은 이 3D mouse 입력 단을 대체하는 위치로 본다. 하류(MQTT → ADS → TwinCAT)는 그대로 둔다

# 진행

## 2026-10-05 — 1차 검토: 가능 여부와 위치 측정 방식

### 1. 결론
- 구현 가능. PC 쪽 IK는 기존 C++ 코드(`claude_ws/cpp` 의 `RobotArm7::ik()`, `solveIk()`)와 RA/LA 파라미터 구조를 그대로 쓴다
- 설계를 좌우하는 것은 **폰의 위치를 어떻게 얻느냐**이다. 자세는 IMU만으로 충분하다

### 2. 전체 구성안

```
[폰 A (앱)] ─USB─┐  adb -s <A> reverse tcp:5001 tcp:5001
[폰 B (앱)] ─USB─┤  adb -s <B> reverse tcp:5002 tcp:5002
                ▼
[PC 프로그램 (C++)]
  ├ 포즈 수신 (TCP, 폰 1대당 포트 1개)
  ├ 클러치 매핑: 버튼을 누른 순간의 폰 포즈 P0, 로봇 끝단 포즈 E0 기록
  │    E_des = E0 · (P0⁻¹ · P)   (스케일·축 변환 포함)
  ├ 필터 + 속도/작업공간 제한
  ├ RobotArm7::ik() ×2 (RA ← 폰 A, LA ← 폰 B), 직전 해를 초기값으로 사용
  └ 관절 명령 출력 (MQTT q 송신 또는 MuJoCo 시뮬)
```

- **USB 통신**: `adb reverse` 로 폰 앱이 `localhost` 에 접속하고, 실제 트래픽은 USB로 흐른다. Wi-Fi가 필요 없고 지연은 수 ms 수준이다
- **좌표계**: 두 폰의 기준 좌표계는 서로 다르다. 절대 좌표를 맞추지 않고 **클러치(상대) 매핑**으로 각 팔을 독립적으로 매핑하면 캘리브레이션이 필요 없다 (VR 텔레오퍼레이션의 표준 방식)
- **안전**: 폰 화면의 데드맨 버튼을 누르고 있는 동안만 추종하고, 떼면 정지 후 재클러치한다. IK 실패나 관절 한계 근접 시 정지하고, 끝단 속도와 가속도에 상한을 둔다

### 3. 위치에 카메라가 필요한 이유

- **자세**: 자이로를 1회 적분하면 얻는다. 중력 방향(가속도계)과 지자기(자력계)라는 **절대 기준**으로 계속 보정되므로 장시간 안정적이다
- **위치**: 가속도를 **2회 적분**해야 하는데, 폰 안에는 위치를 보정해 줄 기준 센서가 없다. 오차가 t²로 커진다

일정 가속도 오차 b → 위치 오차 x = ½·b·t²

| 오차 원인 | b | 1초 후 | 10초 후 |
|---|---|---|---|
| 가속도계 바이어스 (폰급 MEMS) | ~0.02 m/s² | 1 cm | 1 m |
| 자세 1° 오차 → 중력 9.81 m/s²가 덜 빠짐 | 9.81·sin1° ≈ 0.17 m/s² | 8.5 cm | 8.5 m |

- 가속도계는 중력까지 함께 재므로 자세로 중력을 빼야 한다. 자세가 1°만 틀려도 그 잔여분이 "움직임"으로 적분된다
- **ARCore**(카메라 + IMU 융합 VIO)는 주변 특징점이라는 고정된 외부 기준으로 드리프트를 계속 리셋한다. 6DoF 포즈를 cm 수준, 30~60 Hz로 제공한다
  - 조건: ARCore 지원 기종이어야 하고, 후면 카메라가 가려지지 않아야 하며, 질감 있는 환경이 필요하다
- 카메라 없이 위치 기준을 얻는 대안: 외부 트래커(PC 웹캠 + ArUco 마커, Vive Tracker, OptiTrack 등)

### 4. 상대 좌표로 하면?

- 상대 좌표가 해결하는 것은 **좌표계 정렬 문제**뿐이고, 드리프트는 해결하지 못한다. 시작점 대비 이동량 Δp = ∬a dt² 역시 같은 2회 적분이다
- 다만 텔레오퍼레이션에서는 **사람이 로봇을 보며 보정**하므로(마우스와 같은 원리), 1:1 정확도 대신 다음 두 가지만 만족하면 쓸 만하다
  1. 손이 움직이면 로봇도 대략 그 방향과 크기로 움직인다
  2. **손이 멈추면 로봇도 멈춘다**
- 2번은 **정지 검출(ZUPT, Zero-velocity Update)**로 확보한다
  - 판정: 자이로 ≈ 0 이고 |가속도| ≈ g 인 상태가 수십 ms 이상 이어짐
  - 처리: 정지 순간마다 속도를 0으로 리셋한다. 드리프트가 "움직이는 구간"으로 제한된다
  - 1회 동작(0.5~1초)당 오차는 수 mm~수 cm 수준이며, 조작자가 다음 동작에서 보정한다
- 한계
  - 느린 움직임에 약하다. 가속도가 노이즈 수준이면 정지로 판정되거나 이동량이 작게 잡혀 미세 조정이 어렵다
  - 1:1 대응이 아니다. 같은 손동작에도 매번 조금씩 다르게 움직인다
  - 빠른 회전과 이동을 동시에 하면 자세 오차가 중력 제거 오차로 번져 튈 수 있다. 로봇 측 속도·가속도 상한이 필수다

### 5. 방식 비교

| 방식 | 필요한 것 | 위치 품질 | 난이도 |
|---|---|---|---|
| IMU + ZUPT (상대) | 폰만 | 마우스 수준, 대략적 | 낮음 |
| ARCore (상대) | 폰 카메라 시야 확보 | 1:1, cm 수준 | 중간 |
| 외부 트래커 | 웹캠+마커 또는 Vive 등 | 1:1, mm~cm 수준 | 중간 |

### 6. 권장 진행
- 자세는 IMU(Game Rotation Vector)를 사용하고, 위치는 **IMU + ZUPT로 먼저 구현**한다. 폰 앱은 센서값과 버튼 상태만 송신하면 된다
- 부족하면 위치 소스만 ARCore 또는 외부 트래커로 교체한다. PC 쪽 클러치 매핑과 IK 구조는 그대로 유지한다
- 검증 순서: MuJoCo 모델(`claude_ws/mujoco`)로 시각화 → 실기

### 7. 미결 사항
- 출력 대상: 기존 MQTT q 송신 경로에 붙일지, 우선 MuJoCo 시뮬만 할지
- 위치 추종이 필요한지, 자세만으로 충분한지
- 폰 기종의 ARCore 지원 여부
- PC의 Android 빌드 환경(Android Studio / SDK) 유무

## 2026-10-06 — 시뮬레이션 구현 (USB + Wi-Fi)

- 구현 위치: `claude_ws/teleop/` (사용법·검증 결과는 그 README)
  - 폰 앱(Java, Gradle 없이 SDK 툴로 빌드), PC `teleop_sim.py`(Python + MuJoCo)
  - USB와 Wi-Fi는 **같은 TCP 서버** 하나로 처리한다. USB는 `adb reverse`, Wi-Fi는 UDP 비컨으로 PC 주소를 찾는다
  - 폰 1대당 포트를 나누지 않고 한 포트(5001)를 공유하며, 앱에서 고른 팔(RA/LA)로 구분한다
- 출력은 MuJoCo 위치 서보 모델이다. IK는 같은 rmd에서 만든 MuJoCo 모델의 자코비안으로 푼다(DLS)
- 연결된 폰 **Galaxy A15(SM-A155N)는 자이로가 없다** (가속도계 + 지자기만)
  - 자세는 GEOMAGNETIC_ROTATION_VECTOR로 대체한다. 저속에선 쓸 만하지만 동작 중 흔들림·자기 간섭이 있다
  - IMU 위치(ZUPT)는 이 폰에서 불가하다(중력 분리 불가). 위치 입력으로 **터치 드래그**를 추가했다
  - ARCore도 자이로가 필요하므로 이 기종에서는 쓸 수 없다
- 7절 미결 사항 갱신: 출력 대상 → 우선 MuJoCo 시뮬 / Android 빌드 환경 → 있음(SDK 35~36, Android Studio JBR 21) / ARCore → 현 기종 불가
- (같은 날 변경) 사용자 결정으로 **모션 센서를 쓰지 않고 조그 버튼 방식**으로 바꿨다. 가로 화면 왼쪽 LA / 오른쪽 RA 패드, X±·Y±·Z±·Rx±·Ry±·Rz±를 누르고 있는 동안 일정 속도로 이동하며, 수신이 0.2초 끊기면 정지한다. 위 센서 관련 항목(IMU/ZUPT, 터치 위치)은 코드에서 제거됐다
- (같은 날 변경 2) **IK를 폰에서 풀고 폰이 MQTT `/humanoid/upper/cmd/joint`로 직접 발행**하도록 바꿨다(PC 경유 없음). 폰 3D 뷰는 실제 CAD 메쉬, 연결 시 `joint_state`로 현재 자세 동기화 후 발행, 서보 플래그 기본 0, 관절 한계는 실기 측정 가동 범위. PC `teleop_sim.py`는 내장 브로커 + MuJoCo 로봇 대역. 상세는 `claude_ws/teleop/README.md`
